# Deploying LADLI on Render (free) and Vercel

Two independent, zero-cost paths. **Render is the recommended one** — the admin
panel, sessions, visitor counter and PostgreSQL all work out of the box.

---

## 1. Render — free plan, $0 billing (recommended)

Everything is declared in [`render.yaml`](render.yaml): one free **Web Service**
plus one free **PostgreSQL** database. No credit card is required.

### Steps

1. Push this branch to GitHub (already done).
2. Render Dashboard → **New +** → **Blueprint** → connect the repo → select the
   branch → **Apply**.
   Render reads `render.yaml`, creates:
   * `ladli-db` — free PostgreSQL (`ladli_db`, user `ladli_app`)
   * `ladli` — free Python web service running
     `gunicorn -c gunicorn.conf.py app:app`
3. When prompted (or afterwards in **Environment**), fill the two secrets that
   are intentionally not stored in git:
   * `ADMIN_PASSWORD` — first-run admin password (12+ chars, mixed case, digit,
     symbol)
   * `ADMIN_EMAIL` — optional
   `SECRET_KEY` is auto-generated by Render and `DATABASE_URL` is wired to the
   free database automatically.
4. Wait for the first deploy. Health check: `https://<service>.onrender.com/health`
   must return `{"database":"connected","status":"ok"}`.
5. Log in at `https://<service>.onrender.com/admin/login` with `admin` /
   your `ADMIN_PASSWORD`, then immediately:
   * change the password (Settings), and
   * complete the **security-question recovery setup** (there is no SMTP —
     security questions are the only recovery path).

### Free-tier behaviour (expected, not bugs)

| Item | Behaviour |
|---|---|
| Sleep | The service sleeps after ~15 min idle; the next request cold-starts in 30–60 s. |
| Database | Free PostgreSQL has a limited lifetime shown in the dashboard — export a dump before it expires. |
| Disk | Ephemeral. Quote-attachment PDFs survive only if AWS S3 is configured (`AWS_S3_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`). Everything else lives in PostgreSQL and is safe. |
| HTTPS | Provided by Render automatically; `FORCE_SECURE_COOKIES=true` makes session cookies `Secure` + HSTS active. |

### Why the admin panel works on Render

* Flask server-side sessions (signed cookies) with a stable `SECRET_KEY`.
* `TRUSTED_PROXY_COUNT=1` so the real client IP is read from Render's proxy for
  rate limiting and lockouts.
* Persistent PostgreSQL for admins, security questions, inquiries and visitors.
* `/health` is used as the Render health check path.

## 2. Vercel (serverless) — also free

[`vercel.json`](vercel.json) + [`api/index.py`](api/index.py) route **every**
path into the same Flask app, so the public site and `/admin` both work.

### Steps

1. Vercel → **Add New… → Project** → import the repo → framework preset
   **Other** (the config is auto-detected). No build command needed.
2. Add environment variables (Project → Settings → Environment Variables):

   ```
   DATABASE_URL   = postgresql://user:pass@host/db?sslmode=require   # Neon / Supabase pooler
   PGSSLMODE      = require
   SECRET_KEY     = <64 random hex chars>      # must be fixed, not regenerated
   FLASK_ENV      = production
   FORCE_SECURE_COOKIES = true
   TRUSTED_PROXY_COUNT  = 1
   ADMIN_USERNAME = admin
   ADMIN_PASSWORD = <strong password>
   AWS_S3_BUCKET / AWS_REGION / AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY  # for PDF uploads
   ```
3. Deploy, then check `/health` and log in at `/admin/login`.

### Serverless caveats you must accept

* **Bring your own PostgreSQL.** Vercel has no managed Postgres in this
  blueprint — use a free Neon or Supabase database and paste its pooled
  connection string into `DATABASE_URL`.
* **Read-only filesystem.** `ATTACHMENT_DIR` is forced to `/tmp`, which is
  wiped between invocations, so **S3 is mandatory** if you want quote PDFs to
  survive. Without it, uploads succeed but the file may vanish.
* **In-memory rate limiting is per-instance**, so the login lockout is weaker
  than on Render (each lambda has its own counter). The database-backed
  failed-login lockout still applies.
* `SECRET_KEY` must be set explicitly — otherwise every cold start invalidates
  all admin sessions.

Because of these three points, use **Render for the real admin panel** and treat
Vercel as an optional mirror/preview of the same codebase.

## Post-deploy checklist (both platforms)

- [ ] `/health` → `{"database":"connected","status":"ok"}`
- [ ] Home page loads with images and correct caching headers
- [ ] `/api/visitor-count` increases once per unique visitor (not per refresh)
- [ ] Contact and Quote forms submit; the inquiry appears in the admin dashboard
- [ ] Admin login works; wrong password gives the generic error and locks out
      after repeated failures
- [ ] Password change forces re-login (session fingerprint invalidation)
- [ ] Security questions set up, and `/admin/forgot-password` recovery works
- [ ] Admin panel usable on a 360 px wide phone (sidebar drawer, Esc to close)
